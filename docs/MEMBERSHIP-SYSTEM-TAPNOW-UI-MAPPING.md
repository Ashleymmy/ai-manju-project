## 4. TapNow 独有概念 —— 决策记录（✅ 用户已确认）

### 4.1 礼包超市 ✅ 保留

**决策：页面保留，货架内容后定**（用户：「倒时候我看看能上架什么东西，后面再定」）。

- 落地为**后台可配置货架**（套餐配置管理同源），不硬编码任何商品
- 无限日卡（MiniMax H3 $99/天 等 TapNow 玩法）**只是候选货架内容**，不是承诺；若日后上架需先解决「无限使用 vs 积分扣费」的成本冲突（需新增权益通行证实体，结算时优先判 pass 再扣积分）
- 第一期可只出页面骨架 + 「敬请期待」空态，或挂积分类商品

### 4.2 弹性额度滑杆 ✅ 已定：数据按文档，UI 按 TapNow

**决策：定价规则与明细全部按文档，UI 样式参照 TapNow 订阅页**。会员档位已定稿为 **2 个付费档：¥198 / ¥1980**（2026-09-17），免费用户为非会员态。

- 套餐表保持固定档位模型，**不引入「底价 + 积分单价」的弹性定价**
- TapNow 的档内滑杆（3.5k–20k）不实现为定价功能；若保留滑杆视觉，仅作档位切换器（拖动吸附到固定档），价格联动由套餐配置表驱动
- 卡片布局、划线价、最受欢迎徽标、随档权益列表等视觉元素照搬；卡片数量从 4 张减为 **2 张付费卡 + 免费态说明**

### 4.3 兑换码中心 ✅ 采纳，延后

**决策：与邀请码并存，成本低，可延后**（用户确认）。

- 工单 WP-M14，排在邀请有礼（WP-M9）之后
- 一张兑换码表 + 核销接口 + 用户端单输入框页面（参考图 7 形态）

### 4.4 用量热力图 ✅ 第一期不做

**决策：第一期只出文档要求的统计卡**（图片次数 / 视频秒数 / Agent 次数）。

- 热力图 + 单日峰值/连续活跃天数记入 backlog（WP-M16）
- 数据从积分流水聚合即可，届时无需改模型

### 4.5 发票 ✅ 预留字段

**决策：订单表预留 `invoice_status` 字段，第一期只放「联系客服开票」入口**，不接电子发票 API。

### 4.6 支付与币种

TapNow 是**银行卡 + USD + 币种切换**；我们文档是**支付宝 / 微信 / 平台余额 + CNY**。布局照搬，币种切换砍掉，支付渠道按文档。

## 5. 文档有、TapNow 没有 —— 自建（不死抄，按我们的需求改造）

> 用户原则：这些模块**功能与数据以文档为准**，UI 参照 TapNow 的深色组件语言重新组合，不强行套用 TapNow 没有的页面。

1. **双余额体系**（永久/限时 + 限时优先扣减 + 31 天清零）——TapNow 是单一额度池（固定额度进度条）。我们的账号下拉、会员首页、消耗明细都必须体现两个池子：
   - 账号下拉：两行余额（`限时积分 xx · x天后清零` / `永久积分 xx`）+ 等级徽标，替代 TapNow 的单一进度条
   - 会员首页：双余额卡并排 + 「优先扣除限时积分」提示（沿用 image14 原型文案）
   - 消耗明细：每行标注积分类型（限时/永久），筛选器加「积分类型」维度
2. **积分流水 7 类型**——TapNow 账单只有支付记录；我们的消耗明细页在账单表格基础上**加「流水类型」列与筛选**（充值购买/会员月发/任务消耗/后台调增/后台调减/过期扣减/活动赠送），状态胶囊样式沿用图 6
3. **邀请有礼**（邀请码 + 双方奖励 + 首充绑定 + 待发放状态）——页面形态参考图 7 奖励中心的简洁卡片式，内容按 image17 原型（邀请码 + 复制链接 + 二维码 + 奖励规则 + 记录 + 明细）
4. **后台 8 模块**全部（TapNow 参考图全是用户端）——UI 沿用 studio 现有 admin 面板风格，与 TapNow 深色体系一致
5. **失败/取消不扣费**的结算闭环（参考图无此语义）——账单/明细中失败与取消任务显示 `0` 或「未扣费」徽标，不显示扣减数值（修正 image9/image15 原型的瑕疵）
