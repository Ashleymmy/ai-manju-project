# 画布缩略图与原图详情分离

## 原因

大图预览与画布节点原先共用 `imageSrcFromNode(node, previews)`。`previews` 是资产接口的 640px 缩略图缓存，因此详情弹窗实际加载的是缩略图，解码后的分辨率也是缩略图分辨率。

## 修改

- 画布缓存改为请求现有 320px 缩略图规格，等比缩小；视频与音频不缩放。
- 打开详情时使用独立的原图加载 hook，请求资产内容接口且不带 `thumbnail` 参数，不复用缩略图缓存。
- 分辨率取大图元素的 `naturalWidth` / `naturalHeight`，文件大小取原图 Blob 的 `size`，不使用节点显示尺寸或旧 bytes 元数据。
- 详情立即打开并显示加载提示；失败支持重试，不退回缩略图冒充原图。快速切换、关闭时取消请求并释放对象 URL，防止旧图与新图信息混用。
- 历史直接链接节点读取其直接原图地址。外部链接若禁止跨域读取文件内容，仍可尝试直接显示原图，但文件大小显示未知。
- 不新增固定 1000×1000 的尺寸，不放大或修改原文件。后端现有原图/缩略图路由已支持此行为，无后端修改。

## 下载与导出补充检查

用户明确要求下载/导出也保留原图，1000×1000 仅为举例。本轮统一单张节点和详情下载的原文件读取逻辑，禁止工作区未确认或原文件请求失败时退回缩略图；直接链接下载检查 HTTP 状态。完整画布归档直接读取原文件 Blob，避免创建多余的临时预览 URL。后端批量导出经源码检查使用 `copyAssetToZip` / `io.CopyBuffer` 原样复制原文件，不缩放、不重编码。
